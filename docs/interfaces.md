## 1. Pipeline and artifacts

```
prepare_corpus.py    ──► data/clean/{train,val}/*.txt
train_tokenizer.py   ──► data/tokenized/tokenizer.json      (train split only)
encode.py            ──► data/tokenized/{train,val,tiny}.bin + meta.json
test_roundtrip.py    ──► pass / fail
train.py             ──► one row appended to results/runs.csv (rank 0 only)
check_correctness.py ──► fills the `valid` column of results/runs.csv
```

| Stage | Script | Slurm script | Reads | Writes |
|-------|--------|--------------|-------|--------|
| Corpus | `src/prepare_corpus.py` | `slurm/prep_data.sbatch` | Project Gutenberg (cached in `data/raw/`) | `data/raw/`, `data/clean/train/`, `data/clean/val/` |
| Tokenizer | `src/train_tokenizer.py` | `slurm/tokenize.sbatch` | `data/clean/train/` | `data/tokenized/tokenizer.json` |
| Encoding | `src/encode.py` | `slurm/tokenize.sbatch` | `data/clean/`, `tokenizer.json` | `train.bin`, `val.bin`, `tiny.bin`, `meta.json` |
| Round-trip check | `src/test_roundtrip.py` | `slurm/tokenize.sbatch` | all of the above | exit code |
| Training | `src/train.py` | `slurm/job_*.sbatch` | `data/tokenized/` | `results/runs.csv` |
| Smoke test | `scripts/pipeline_tiny.sh` | `slurm/cpu_smoke.sbatch` | `data/raw/` | `data/tokenized_smoke/`, `results/smoke_runs.csv` |
| Correctness | `src/check_correctness.py` | none (run after each job) | `results/runs.csv` | `results/runs.csv` (`valid` only) |

Nothing under `data/raw/`, `data/clean/`, `data/tokenized/` or
`data/tokenized_smoke/` is committed; every stage is regenerated by its script.

## 2. Data format

Full spec: `data/README.md` (corpus catalog, split, tokenization, per-work counts).
The parts other code depends on:

| Item | Value |
|------|-------|
| Clean text | UTF-8, one `.txt` per work; `data/clean/train/` (25 works), `data/clean/val/` (5 works, held out whole) |
| Tokenizer | Byte-level BPE, Hugging Face `tokenizers`, trained on the train split only |
| Vocabulary | **8,192** (not 8,000), including one special token |
| Special token | `<\|endoftext\|>` = id **0**, appended after every work |
| `.bin` format | flat little-endian **uint16** token ids, no header |
| Loading | `np.memmap(path, dtype=np.uint16, mode="r")` |
| `tiny.bin` | first 1,500,000 tokens of `train.bin` (a prefix) |
| `meta.json` | vocab size, dtype, EOT id, token count per split (`splits.<name>.tokens`), SHA-256 of every file |

Validation always reads `val.bin`, also when training on `tiny.bin`.

## 4. `results/runs.csv`

Full spec: `results/README.md` (33 columns, timing method, exposed-communication
method). `src/runlog.py` holds the column list and refuses rows that do not match
it, so `results/README.md` and `runlog.COLUMNS` always change together.

- Only `train.py` (rank 0) appends rows. Nobody adds or edits rows by hand.
- `results/runs.csv` holds experiment runs only (jobs A–E, `opt`, `final`).
  Smoke and development runs (`--job smoke`, `--job dev`) go to
  `results/smoke_runs.csv`, which is git-ignored; their evidence is the Slurm log.
- A run that crashes gets a row with `status = failed`. A job that never runs
  gets a row with `status = SKIPPED` and the reason in `notes`. No row is ever deleted.
- `valid` is left empty by `train.py`. Only `src/check_correctness.py` writes it,
  and it writes nothing else.

## 5. Correctness rule and run conventions

**Rule** (README): a run is valid if its validation loss after 500 steps is within
2% of the single-GPU fp32 baseline, same seed, same global batch.

Operational definition used by `src/check_correctness.py`:

- **Baseline rows:** `precision = fp32`, `world_size = 1`, `status = ok`, non-empty
  `val_loss_500`.
- **Matching:** a run is compared with the baseline rows that share `n_layer`,
  `n_embd`, `n_head`, `seq_len`, `global_batch`, `seed`, `steps`, `device` and
  `gpu_model`. `steps` is `--max_steps`: the cosine learning-rate schedule ends at
  `max_steps`, so the learning rate at step 500 depends on it.
  The reference is the **median** `val_loss_500` of those rows.
- **Test:** `|val_loss_500 − reference| / reference ≤ 0.02` → `yes`, otherwise `no`.
  Baseline rows are tested against their own median, so a baseline that disagrees
  with its repeats is flagged too.
- **`n/a`:** `status` is not `ok`, `val_loss_500` is empty (run shorter than 500
  steps), or no matching baseline exists (the printed reason names the columns that
  differ from the closest baseline). The reason is printed, not stored.

Consequences for the experiment plan:
- Any run that must pass the rule needs ≥ 500 steps and an fp32 single-device
  baseline with identical settings on the same device.
- Runs checked against the rule use **`--max_steps 500`**, like the Job A baseline.
  They also keep the default `--lr`, `--min_lr` and `--warmup_steps`: these change
  the loss at step 500 too, but `runs.csv` does not record them, so the checker
  cannot catch a mismatch.
- Job B needs its own fp32 baseline on julia; it is not judged against haskell.
- The Job A sequence-length sweep (100 steps) gets `n/a`: it is a timing
  measurement, not a correctness check.

**Conventions**

| Item | Convention |
|------|------------|
| Seed | 1337 for every run unless an experiment varies it on purpose |
| Repeats | 3 per configuration; analysis uses the median |
| `experiment` labels | lowercase, `_`-separated, repeat index last: `baseline_fp32_r1`, `baseline_bf16_r2`, `seqlen512_fp32_r3`, `ddp_ws2_r1`, `ddp_p2p_off_r1`, `crossnode_ws2_r1`, `cpu_threads16_r1`, `opt_<name>_r1`, `final` |
| Python on the cluster | `module load pytorch/2.8.0`, then run every script with `torch-python` |
| Where to run | Slurm jobs only; never on the login node |
| Slurm account / QoS | not set; the cluster assigns them (assignment §7) |
| Logs | `#SBATCH --output=slurm/logs/<name>_%j.out`; every log is committed |

**Environment variables** set by the Slurm scripts (recorded for reproducibility):

| Variable | Value | Set in |
|----------|-------|--------|
| `OMP_NUM_THREADS` | `$SLURM_CPUS_PER_TASK` (halved per rank for 2-process CPU DDP) | all training scripts |
| `TOKENIZERS_PARALLELISM` | `true` | `slurm/tokenize.sbatch` |
| `RAYON_NUM_THREADS` | `$SLURM_CPUS_PER_TASK` | `slurm/tokenize.sbatch` |
| `NCCL_P2P_DISABLE` | `1` only in the P2P-off runs of job C; unset otherwise (`nccl_p2p_disable` column) | job C |

## 6. Branches and pull requests

- No direct pushes to `master`; everything arrives through a PR.
- One branch per task: `feature/<name>`, `fix/<name>` or `docs/<name>`.
- Keep PRs small and merge often. Persons 3 and 4 both edit `train.py`, so they
  rebase on `master` before opening a PR.
- A PR is mergeable when:
  1. it follows this file (flag names, file paths, CSV columns, data format);
  2. `slurm/cpu_smoke.sbatch` passes on the branch (link the job ID in the PR);
  3. Person 6 has approved it, plus the owner of any file it changes.
- A PR that changes an interface edits this file in the same PR and starts its
  title with `[interface]`.
- Slurm logs that serve as evidence are committed in the PR that produced them.
